## ROOT_CAUSES

1. **[PRIMARY][a,b] HLS session is advertised/join-counted before media is playable.**
   - `app/live-viewer.js:533-538` sends `live_join` immediately after WS auth.
   - `app/live-viewer.js:540-548` accepts `cf_hls` + `hls_url` but does no manifest/first-frame readiness backoff.
   - `app/live-viewer.js:439-452` fires generic `Stream indisponível` after timeout even for Cloudflare HLS warm-up.
   - `app/live-broadcast.js:395-401` host trusts `live_viewer_count`; count increments even if viewer never decodes HLS.

2. **[PRIMARY][a] Broadcast file has no RTMP/WHIP publish path for Cloudflare Stream.**
   - `app/live-broadcast.js:684-710` calls `api.liveStart(...)`, then only starts WS signaling.
   - `app/live-broadcast.js:493-577` still creates per-viewer WebRTC P2P offers.
   - No code consumes `rtmp_url`, `stream_key`, `whip_url`, etc. If backend created a CF live input, nothing in this screen publishes camera/mic to it.

3. **[PRIMARY][b] Host starts signaling after camera + API + 3s countdown; live may be discoverable before WS `live_start` is acked.**
   - `app/live-broadcast.js:684-706`: `api.liveStart` happens before countdown.
   - `app/live-broadcast.js:693-699`: waits 3/2/1.
   - `app/live-broadcast.js:701`: only then `connectSignaling()`.
   - `app/live-broadcast.js:346-363`: ack watchdog sets error but `handleStartLive` never awaits ack.

4. **[CONTRIBUTING][a,b] Viewer count source is mixed.**
   - `app/live-broadcast.js:395-401`: WS server count is authoritative.
   - `app/live-broadcast.js:552,576`: local P2P `peersRef.size` overwrites `viewerCount`.
   - `app/live-broadcast.js:704-708`: periodic `api.liveUpdateViewers(..., peersRef.current.size)` reports `0` for HLS sessions.

5. **[PRIMARY][c] End-live modal races keyboard dismissal.**
   - `app/live-broadcast.js:721-731`: `Keyboard.dismiss(); setKbHeight(0); setEndModal(true)` same tick.
   - No `TextInput` ref blur, no wait for Android `keyboardDidHide`, modal likely mounts while bottom UI is still keyboard-offset.

6. **[PRIMARY][d] Replay save UI mutates local state after `liveEnd` already used the previous value.**
   - `app/live-broadcast.js:648-669`: `api.liveEnd(endedSessionId, { save_replay: saveReplay })`.
   - `app/live-broadcast.js:890-905`: end-card “Salvar replay” button toggles `saveReplay` after teardown; no API call.
   - `app/live-broadcast.js:910-929`: “Ver Lives Salvas” appears only after async `has_recording`, with no “processing/saved in Lives” explanation.

7. **[PRIMARY][e] Collab signaling payloads do not match + ICE is dropped.**
   - Host approve omits host identity: `app/live-broadcast.js:914-920`.
   - Viewer sends guest offer without stable `guest_id` / `guest_email`: `app/live-viewer.js:646-653`.
   - Host answer uses `msg.guest_id`: `app/live-broadcast.js:613-620`; can be `undefined`.
   - Host guest ICE handler drops ICE if `guestPeer` state has not committed: `app/live-broadcast.js:626-630`.
   - Viewer join retry timers are not stored/cleared: `app/live-viewer.js:1038-1068`.

8. **[CONTRIBUTING][e] P2P guest is not mixed into HLS.**
   - `app/live-broadcast.js:586-657` renders guest as host PiP only.
   - No SFU/compositor/RTMP mixer path, so HLS viewers will not see the guest.

9. **[PRIMARY][f] Chat overlay retains unbounded message state.**
   - Host appends forever: `app/live-broadcast.js:404-419`, `536-553`, `645-662`.
   - Viewer appends forever: `app/live-viewer.js:839-857`, `866-884`.
   - `components/live/LiveChatOverlay.js:39` renders only `messages.slice(-6)`, but parent keeps all messages + `Animated.Value`s.

## RACE_CONDITIONS

- Use WS generation tokens in both host/viewer; ignore stale `onclose/onmessage`.
- Null WS handlers before `close()` to prevent old socket scheduling reconnect over new socket.
- Reset `liveStartedAckRef` per start/reconnect; await `live_started`.
- Queue ICE by peer id / guest id until `remoteDescription` exists.
- Close existing `pcRef.current` before accepting a new `live_offer`; clear old ICE queue.
- Store retry timers in refs and clear on unmount: HLS retry, join-request retry, end modal timer, reconnect timer.
- Do not call `setState` from `liveEnd(...).then` after unmount; add `mountedRef`.
- Do not mutate `saveReplay` after `performEndLive`; freeze the value used for API.
- Keyboard modal: blur input, dismiss keyboard, delay/open after hide.

## RISKS

- Awaiting `live_started` requires backend to always echo it; otherwise start fails after 5s.
- Removing local `peersRef.size` count requires WS `live_viewer_count` to be reliable for legacy P2P.
- HLS retry can mask true 404 for up to 90s; verify ended/deleted sessions still fail fast via `live_ended`/API status.
- Native RTMP publisher requires dev-client/native rebuild, camera/audio permission retest, thermal/battery testing.
- Collab remains host-only unless SFU/mixer/RTMP compositing is added.
- Chat cap drops old in-memory messages; full chat sheet should fetch history from API if older messages needed.
- End modal delay may feel slightly slower on Android; verify hardware keyboard and gesture nav cases.
